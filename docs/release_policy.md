# 提交、版本与发布说明

Try 采用 [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/) 和 [SemVer 2.0.0](https://semver.org/spec/v2.0.0.html)。

## 提交

标题格式为 `type(scope)!: 描述`；`scope` 和 `!` 按需使用。描述使用中文，简要说明结果；type 与 scope 使用小写英文，scope 可使用 snake_case。

| 类型 | 用途 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 问题修复 |
| `perf` | 性能改进 |
| `refactor` | 保持行为的代码整理 |
| `docs` | 文档与维护规则 |
| `test` | 测试 |
| `build` / `ci` | 构建、依赖或持续集成 |
| `style` / `chore` | 格式或其他维护 |
| `revert` | 撤销既有改动，正文说明对应提交与影响 |

这是项目选用的类型集合与语言约定。正文与标题空一行，按需说明原因、行为变化和验证结论；单次验证输出仍按[仓库内容规则](development.md#仓库内容)保存。

不兼容变化必须用标题中的 `!` 或页脚 `BREAKING CHANGE:` 标识。Try 还要求说明受影响的用法、数据迁移或替代方法；即使采用 `!`，也要保留这些说明。

```text
feat(packs): 支持图片题面
fix(ui): 修复卡片收起后的位置
docs: 统一提交与发布规范
```

反馈与调试先保留在工作区；需要本地检查点时保存到本地生成目录。保存里程碑或准备发布时，将同一改动的实现、必要文档和验证结论整理为一个完整提交。公开 PR 可使用 Squash and merge；整理后的标题按实际变化选择类型，正文保留同时交付的修复与不兼容变化。

一个版本可包含多个完整批次。公开或共享后的主分支保留有意义的增量历史，不为凑成“全仓库一个提交”改写既有历史。

克隆后按[开发说明](development.md#提交规范)启用现有提交钩子与[模板](commit_template.txt)。钩子检查标题格式和中文描述；改动类型、兼容性与迁移说明由审阅确认。

## 版本

程序版本使用 `MAJOR.MINOR.PATCH`，例如 `1.0.0`。Git 标签加 `v`，例如 `v1.0.0`。根 `Cargo.toml` 的 package version 是程序版本来源，发布时同步锁文件中的本项目版本。界面、内嵌版本、标签、版本化附件名称和校验记录必须对应同一版本。

从 `1.0.0` 起，兼容范围覆盖已文档化的知识包 JSON、命令行用法、受支持平台及用户可见行为。同一主版本内的更新保留设置、题库、图片和学习记录，格式变化须验证迁移和回退。知识包有独立的格式版本，见[知识包格式](knowledge_pack_format.md)。

升级自 `0.x` 时沿用可读取的数据。预发布版的数据格式和升级路径不在正式版兼容承诺内，升级前建议备份完整数据目录。

| 正式版的变化 | 版本调整 |
| --- | --- |
| 兼容的修复或性能改进 | PATCH |
| 兼容的新功能或公开功能弃用 | MINOR |
| 不兼容变化，包括移除已支持的用法或平台 | MAJOR，并说明迁移方式 |
| 仅文档、测试或维护流程变化 | 无需发布程序版本 |

按本次发布中影响最高的变化决定版本，升 MINOR 时 PATCH 归零，升 MAJOR 时 MINOR 与 PATCH 归零。类型与影响需要一致；版本号不按提交数量、构建次数或依赖版本机械递增。独立组件维护自己的版本，Try 根据接入后的实际影响升版。

正式版使用三段版本号，发布到 GitHub 时设为正式发布。正式客户端只提示已公开的稳定版本。若公开预发布候选，使用如 `1.1.0-rc.1` 的版本号并勾选 GitHub 的预发布标记。`+build` 元数据不影响版本排序。

每个正式版本对应固定的构建提交。更正程序或必要分发内容时发布新版本，说明勘误可直接在文档中修正。

## 发布说明

版本说明集中写在对应的 GitHub Release 正文。标题使用版本标签，正文简要说明本版实际交付的用户可见变化和必要的升级提示。不兼容变化、弃用或移除需要说明影响，涉及迁移时写明处理方法。内容较多时，分类可参考 [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/)。

[历史变更记录](../changelog.md) 收录至 `v1.0.2`。

## 分发版本核对

公开版本的标签、程序包和 Release 标题使用同一版本号。固定来源、三平台软件包、许可和更新行为的核对方法见[分发验证](release_checklist.md#分发验证)。
